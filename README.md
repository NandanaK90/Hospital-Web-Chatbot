# City Care Hospital: Website with RAG Chatbot

A hospital website built in React, with a floating chatbot that answers
questions from the hospital's own text file. Sample project for learning.

## How it works (theory)

### What is RAG?
RAG means **Retrieval-Augmented Generation**. A plain LLM does not know
anything about our hospital and may guess wrong. RAG fixes this in two steps:

1. **Retrieve**: find the parts of our own data that match the question.
2. **Generate**: give those parts to the LLM and tell it to answer only from them.

This way the answers come from our data, not from the model's imagination.

### Part 1: Preparing the data (runs once, `ingest.py`)
1. **Read** the hospital text from `data/docs`.
2. **Chunk**: cut the text into small pieces, so a question can match one
   small topic (for example, only the OP timings).
3. **Embed**: an embedding model (`all-MiniLM-L6-v2`) turns each chunk into a
   list of 384 numbers that represent its meaning. Similar meanings give
   similar numbers.
4. **Save** the numbers to `index/vectors.npy` and the text to
   `index/chunks.json`.

Run `ingest.py` again every time the text file changes.

### Part 2: Answering a question (every chat message, `rag.py`)
1. The user types a question in the chat box.
2. The question is turned into numbers with the same embedding model.
3. **Search**: compare the question's numbers with every chunk
   (cosine similarity) and take the top 3 matches.
4. **Score check**: if the best score is below `MIN_SCORE` (0.25), the bot says
   "Sorry, I don't have that information." and the LLM is not called.
5. **Prompt**: the 3 chunks plus the safety rules plus the question are sent
   to the Gemini LLM.
6. The LLM writes a short answer, and the answer is shown with its source file.

### Request flow

```
Browser (React site, floating chat box)
   |  POST /chat  { question }
   v
Vite dev server (proxy sends /chat to Python)
   v
FastAPI (app.py)
   v
rag.py:  question -> embedding -> search top 3 chunks
         -> score too low?  -> "Sorry, I don't have that information."
         -> otherwise: build prompt -> Gemini API -> answer
   v
Answer + source  ->  shown in the chat box
```

### Safety rules in the prompt
- Answer only from the given context.
- Never give medical advice, diagnosis or medicine suggestions.
- For health problems, tell the user to consult a doctor.
- For emergencies, tell the user to call the emergency number.

## Project structure

| File / folder | Purpose |
|---|---|
| `data/docs/` | Hospital text (the knowledge) |
| `ingest.py` | Builds the search index |
| `rag.py` | Search + prompt + Gemini call |
| `app.py` | FastAPI server with the `/chat` endpoint |
| `chat.py` | Test the bot in the terminal |
| `frontend/` | React website and chat widget |
| `index/` | Generated by `ingest.py` (not in Git) |

## Run it

You need Python 3, Node.js and a free Gemini API key.

### Backend (Terminal 1, main folder)
```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install fastapi uvicorn sentence-transformers numpy pypdf requests
python ingest.py
$env:GEMINI_API_KEY = "your-key-here"
uvicorn app:app
```

### Frontend (Terminal 2, frontend folder)
```powershell
cd frontend
npm install
npm run dev
```

Open http://localhost:5173/ and click **Chat with us**.

## Notes
- Never commit your API key. Set it as the `GEMINI_API_KEY` environment variable.
- The hospital data is fictional sample data.
- The Enquiry Form does not save anything yet.
